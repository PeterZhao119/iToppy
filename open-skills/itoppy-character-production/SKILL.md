# iToppy 角色形象制作

## 适用范围

- 从一张参考图制作新的 Q 版桌宠。
- 为已有角色补齐动作、修正姿态或重做某组动画。
- 将视频或图片素材整理成 iToppy 可运行的透明 Sprite Sheet 角色包。

目标产物是一个**透明 PNG 帧 / Sprite Sheet 角色包**，不是 Live2D、骨骼动画或实时视频解码。

## 先锁角色，再生成

动手前先写一份不可省略的角色识别清单：

- 头身比、脸型、眼睛和发型。
- 头饰、服装、裙摆、围巾、腰带等结构。
- 特殊道具和特殊部位，例如尾巴、翅膀、企鹅头套、手持书。
- 双腿、双脚、道具与特殊部位的关系。
- 性格关键词和表情边界。
- 哪些元素必须保留，哪些参考图元素必须去掉。

角色性格不能只写“可爱”。要写成可表演的行为，例如：

- DeepSeek：温柔女仆，思考认真，待机轻柔。
- Claude：傲娇大小姐，克制、优雅、失败时维持体面。
- GPT：冷淡女王，正面操作面板，成功也不浮夸。
- Doubao：活泼自然熟，偶尔社交暴徒但不自知。
- QQ：圆润蠢萌，反应慢半拍。
- Kimi：表面端庄、实际腹黑，偶尔有黑色小幽默。

参考图里的文字、水印、街拍背景和不符合角色的姿势都应主动移除，不能默认模型会替你清理。

## 标准流程

```text
参考图 → Q 版标准全身帧 → 绿幕视频 → 抽帧 → 抠透明 → 统一锚点 → 图集 → 预览回读 → 角色包校验
```

### 1. Q 版标准帧

- 约 3 头身；如果用户要求蠢萌或特殊比例，以用户确认的版本为准。
- 全身完整，双脚完整，服装和道具结构清楚。
- 首版只做一张给用户确认，不要直接量产。
- 需要用于视频时，再生成一张自然站姿“标准帧”。挥手、叉腰等姿态只适合做对应动作，不适合作为所有循环的首尾帧。

### 2. 背景必须是真的绿幕

统一要求：

```text
纯亮绿色 #00FF00
颜色均匀
无渐变、无阴影、无地面、无场景
不要棋盘格假透明
角色自身不要出现绿色
```

绿色背景的价值是让发丝、尾巴、道具和服装围成的区域也能被统一抠除。不要接受“透明棋盘格”图片，棋盘格可能只是画出来的 RGB 像素。

### 3. 图生视频模型

优先用 Seedance 图生视频，参考图同时作为首帧和尾帧：

- 循环动作：4 秒源视频，抽前 2 秒 24 帧。
- 长待机：5 秒源视频，抽 60 帧。
- 桌面显示尺寸低，480p 已足够，不必盲目上高分辨率。
- 固定镜头、固定角色大小，全身不超出画面。
- 首尾帧相同只能说明姿态接近，不保证循环；仍要回读预览。

一次性情绪动作（成功、失败）可以仍用首尾同图生成，但只取前 2 秒，动作完成后停在情绪姿态，不取回自然站姿的段。

### 4. 动作语义

iToppy 当前动作协议以 13 组为基础：

| 动作 | 用途 | 制作要点 |
|---|---|---|
| `idle` | 微动待机 | 不眨眼、不点头、不挥手，只保留呼吸、发梢和裙摆微动 |
| `walk_left/right` | 行走 | 原地走，不出框；右走优先镜像左走 |
| `running.thinking` | 思考 | 小动作加表情递进，不要夸张跳跃 |
| `running.tool_calling` | 工具调用 | 正前方半透明面板，单手操作，另一只手保持角色习惯姿态 |
| `running.searching` | 搜索 | 完整放大镜或明确搜索动作，镜片不能透出绿幕破洞 |
| `succeeded` | 成功 | 一次性动作，`loop:false`，停在情绪姿态 |
| `failed` | 失败 | 一次性动作，`loop:false`，符合角色性格而非一律沮丧 |
| `succeeded_idle` | 成功待机 | 用成功末帧或低强度循环 |
| `failed_idle` | 失败待机 | 用失败末帧或低强度循环 |
| `dragging` | 拖拽 | 双手托腮、睁大眼、懵懂；可按角色调整但要有辨识度 |
| 长待机 ×2 | 随机待机 | 5 秒，体现角色性格，不抢 running 动作 |

## 抽帧与统一规格

本项目已验证的统一规格：

```text
帧尺寸：384×683
排列：6 列，行优先
锚点：底边中心 (192, 683)
帧率：12fps
短动作：2 秒 = 24 帧
长待机：5 秒 = 60 帧
```

右行走用左行走逐帧水平镜像，不要重新生成，避免角色和服装漂移。

如果视频首尾姿态跳变明显，可以对“稳定保持段”做乒乓回环：例如第 11–23 帧正放，再接第 22–12 帧倒放。不要直接重复有明显跳变的端点。

## 抠像与透明验收

- 清除全部绿幕，包括发丝、道具和服装围成的区域。
- 浅色衣服、白发和半透明镜片尤其要检查破洞。
- 半透明面板或放大镜远离脸部时，镜片可能反射绿幕并被抠成透明洞；优先选择道具贴近角色、反射较少的片段。
- 行走视频的绿色阴影可能留下噪点；阴影背景需要比普通 idle 更强的清除。
- 生成、转换或抠像后的每个视觉结果都必须实际回读，不能只看接口返回成功。
- MP4 预览没有透明通道；正式验收看 RGBA 帧和 Sprite Sheet，不能只看绿幕 MP4。

## 角色包结构

```text
package/
  character.json
  thumbnail.png
  spritesheets/
    idle.png
    walk_left.png
    walk_right.png
    running.thinking.png
    running.tool_calling.png
    running.searching.png
    succeeded.png
    failed.png
    succeeded_idle.png
    failed_idle.png
    dragging.png
    idle_<long_1>.png
    idle_<long_2>.png
```

`character.json` 至少记录：

- 角色 ID、名称和版本。
- 帧宽高、锚点、fps、列数。
- 每个动作的文件、帧数、行列、fps、时长和 `loop`。
- `stateMap`，把通用 idle 动作映射到角色自己的长待机。

建议映射：

```json
{
  "stateMap": {
    "running.generic": "running.tool_calling",
    "idle_adjust_skirt": "idle_<long_1>",
    "idle_tail_cuddle": "idle_<long_2>"
  }
}
```

## 机器验收

至少检查：

- 13 组动作齐全。
- 图集均为 RGBA。
- `frame_count = columns × rows`。
- 图集尺寸等于 `384 × columns` 和 `683 × rows`。
- `fps = 12`，时长等于帧数除以 fps。
- 缩略图为 192×342。
- `stateMap` 目标全部存在。
- 成功/失败为 `loop:false`，其余按需求设置。

## 成本、记录与素材边界

每个角色目录都应维护：

- `NOTICE.md`：参考图来源、商标和再分发限制。
- `generation-log.md`：模型、参数、每组结果、修复原因和累计费用。

不要删除失败版本而不记录；失败样本能说明为什么换策略。不要把未授权参考图、密钥或私密路径写入公开文档。

## 常见坑

1. **假透明棋盘格**：重新做纯绿幕，不在棋盘格上补洞。
2. **动作太大**：微动 idle 不允许闭眼、点头和明显身体摆动。
3. **道具破洞**：放大镜、全息面板贴近角色，或换片段。
4. **首尾跳变**：用中间稳定段做乒乓回环。
5. **模型忽略关键动作**：先独立生成动作关键帧，再以关键帧做视频；不要无限文字重试。
6. **一次生成全套**：先做 2–3 组小样给用户确认，再量产。
7. **只看接口成功**：所有图片、视频和图集都要实际回读。
