# iToppy 粗设计 v0.1

状态：评审稿，尚未细化交互尺寸、视觉样式和实现接口。

## 1. 首版产品形态

首版只接入 VS Code 的 Kimi Code，但系统从设计上支持多 Agent 类型：

- 启动后从各 Agent 类型的默认路径发现本机实例。
- 用户在控制面板选择需要展示并监控的实例。
- 每个活跃来源实例对应一只桌宠：IDE 按工作区、CLI 按终端会话区分；首版身份牌为“Kimi Code”，详见 `design/source-instance-lifecycle.md`。
- 同一来源实例的多个 Conversation 聚合到对应桌宠，点击后可选择目标；实例的导航与数据源分离。
- 多 Session 聚合先比较状态优先级，再比较最近活动：有运行中的 Session 时保持 running 并显示数量，由最近活动的运行中 Session 驱动子动作；其他 Session 的完成结果不抢占主状态；没有运行中的 Session 时，才由最近完成的 Session 展示结果和气泡。
- 桌宠负责状态、情绪、响应气泡、跳转和轻量桌面行为。
- 控制面板负责 Agent 管理、官方角色选择和全局设置。
- 内部官方制作管线负责从角色设定图制作全身动作相位图；首版不向用户开放生成入口。

首版不建议把控制面板做成置顶窗口；只有桌宠和气泡常驻桌面。

## 2. 启动与 Agent 自动发现

### 2.1 启动流程

```text
加载内置 Agent 类型注册表
        ↓
读取用户已保存的展示选择和手动目录
        ↓
只检查注册表中的默认路径及用户指定路径
        ↓
合并、规范化路径并去重
        ↓
控制面板展示发现结果，用户选择启用项
        ↓
为启用项建立只读监控并显示对应框架桌宠
```

不扫描整个用户目录或整块磁盘。默认路径由每个适配器声明，可以包含多个候选位置；具体 Kimi Code 路径必须由 P0-1 实机验证后登记。

首次启动建议打开控制面板的 Agent 选择页，不立即把所有发现项全部投放到桌面。后续启动沿用用户选择。

### 2.2 Agent 类型注册表

每种支持的 Agent 声明：

```text
agentType          稳定类型标识，例如 kimi-code
displayName        展示名称，例如 Kimi Code
identityIcon       框架身份图标
defaultPaths       默认发现路径列表
validationRules    判断目录是否属于该 Agent 的规则
adapterVersion     解析规则版本
capabilities       可识别的状态与来源定位能力
```

发现结果记录：

```text
instanceId / agentType / rootPath / displayName
source(auto|manual) / visible / monitoringEnabled
workspaceInfo / lastSeen / health
```

自动发现与手动添加使用同一种实例结构，后续监控和 UI 不需要区分处理。

### 2.3 手动添加 Agent

控制面板提供“添加 Agent”：

1. 选择 Agent 类型，只列出已有适配器的类型。
2. 选择目标目录。
3. 可选修改显示名称。
4. 验证目录存在、可读且符合该类型的基本结构。
5. 保存为手动实例，用户启用后开始监控。

验证失败要说明是路径不存在、权限不足，还是目录内容不匹配。手动实例允许移除；自动实例可以选择隐藏，不修改原框架文件。

### 2.4 展示与监控的关系

建议“展示并监控”使用同一个开关：

- 关闭：隐藏桌宠、停止该实例的文件监听，但保留路径和设置。
- 开启：重新检查增量记录、恢复监控并显示对应框架桌宠。
- 同一框架全部实例关闭时，隐藏该框架桌宠。

这样语义清楚，也避免用户以为已经关闭的 Agent 仍在后台消耗资源。右键隐藏时使用“隐藏并暂停监控”，不使用含糊的“移除”。

## 3. 控制面板粗布局

```text
┌──────────────────────────────────────────────────────────┐
│ iToppy                                                   │
│ [Agent] [形象] [设置]                                    │
├──────────────────────────────────────────────────────────┤
│ 已发现的 Agent                            [重新扫描]      │
│                                                          │
│ [x] Kimi Code                       正在监控 / 2 个会话    │
│     VS Code · <目录摘要>                  [定位] [更多]    │
│                                                          │
│ [ ] 其他已发现实例                                        │
│                                                          │
│ [+ 添加 Agent]                                           │
├──────────────────────────────────────────────────────────┤
│ 仅监控已启用项目 · 所有数据默认仅在本机处理                │
└──────────────────────────────────────────────────────────┘
```

### Agent 页

- 展示/监控开关、身份牌、路径摘要、健康状态、最近活动和会话数。
- 每个 Agent 实例独立设置 idle 游走开关、游走速度和成功/失败气泡开关。
- 添加、重新扫描、移除手动实例、在 Finder 中显示目录。
- 权限不足或格式不兼容时进入对应实例的诊断说明。

### 形象页

- 只展示官方 Q 版人形预设角色。
- 每个 Agent 类型的默认角色，以及单独实例的覆盖选择。
- 角色来源和许可证信息。
- 首版不提供“从图片创建形象”、用户生成或用户导入入口。

### 设置页

- 开机启动、始终置顶、音效和静音。
- 透明区域鼠标行为和减少动态效果选项。
- 本地数据、监控路径和隐私说明。
- idle 游走、游走速度和成功/失败气泡不在全局设置中管理；App 可设置默认值，各来源实例可以覆写。

## 4. 桌宠状态与桌面行为

| 状态 | 人物表现 | 气泡 | 游走 |
|---|---|---|---|
| idle | 日常表情、呼吸和待机动作 | 默认无 | 按当前实例设置 |
| running | 通用忙碌或思考、工具调用、搜索子动作 | 显示当前活动短消息或已产生的公开正文前 50 字，不展示隐藏思考正文 | 暂停 |
| succeeded | 开心表情和成功图标 | 按当前实例设置显示最终响应前 50 字 | 暂停，便于阅读 |
| failed | 沮丧表情和失败图标 | 按当前实例设置显示最终失败摘要前 50 字 | 暂停，便于阅读 |
| succeeded_idle | 安静的满意表情，保留成功标记 | 保持显示，直到用户关闭 | 按当前实例设置 |
| failed_idle | 安静的失落表情，保留失败标记 | 保持显示，直到用户关闭 | 按当前实例设置 |
| interrupted | 短暂表现中断后恢复日常状态 | 无最终结果气泡 | 回到 idle 后按当前实例设置 |

新任务到来时，无论当前展示什么，都收起旧结果并进入 running。

### 4.1 running 子动作

running 是任务主状态，子动作只是当前活动，不改变任务仍在运行这一事实：

```text
running.generic
running.thinking
running.tool_calling
running.searching
```

判断规则：

- 用户提交任务后先进入 `running.generic`。
- 观察到明确的思考、工具调用或搜索输出，并且该会话尚未出现任务级最终成功/失败时，切换到对应子动作。
- 工具或搜索的成功/失败只描述中间活动，不能结束 running。
- 出现新的明确活动时更新子动作；无法识别的活动使用 `running.generic`。
- 暂时没有新输出不自动退出子动作，避免把等待网络误判成 idle。
- 只有任务级最终成功、失败或明确中断才能离开 running。
- 并行活动以最新明确记录驱动展示，视觉切换可做短暂去抖，但不能延迟最终结果。

### 4.2 成功/失败气泡

- 内容取任务级最终响应，不取中间工具输出。
- 纯文本化并合并多余空白，按用户可见字符截取前 50 字，截断时增加省略号；不能按 UTF-8 字节截断。
- 不直接执行响应中的 HTML、Markdown 链接或命令，避免异常渲染和内容注入。
- 气泡提供指向角色的尾部、框架身份色和成功/失败图标。
- 点击气泡正文：激活来源 App，并尽可能定位对应工作区或会话。
- 独立关闭按钮只关闭气泡，不点击跳转。
- 气泡超出屏幕边缘时自动换边，保持完整可读。
- 气泡宽度约为角色宽度的 120%，居中在头顶，最多显示四行。
- 进入 `_idle` 后结果和气泡仍保留，不自动收起；只有用户关闭或新任务到来才消失。
- 每个来源实例可独立关闭结果气泡；关闭后仍展示人物心情和结果图标，并可通过右键菜单打开最新响应。

### 4.3 名字牌与状态图标

- 名字牌位于角色头顶、气泡下方，宽度约为角色的 100%，使用透明背景，不遮挡气泡。
- 名字牌、角色和气泡共享位置变换，游走时一起移动；过长名称省略并保留完整名称提示。
- 图标覆盖 idle、running.generic、thinking、tool_calling、searching、succeeded、failed、succeeded_idle、failed_idle；监控降级使用独立警告图标。

### 4.4 idle 随机行为与游走

- 只在 idle、succeeded_idle、failed_idle 中启用，结果气泡是否展开不影响 `_idle` 随机行为。
- 每隔一段时间随机决策：约 40% 开始游走、40% 播放一种长待机动作、20% 保持原地待机。
- 单次游走目标距离约为当前屏幕宽度的 15%，方向随机，并限制在显示器可用区域内。
- 游走开关和速度按 Agent 实例独立保存；关闭游走仍允许随机长待机动作。
- 长待机动作播放一个周期后回到对应 idle；游走结束后随机停留，再决定后续行为。
- running、新鲜 succeeded/failed、拖动和打开菜单时立即暂停随机行为。
- 用户开启“减少动态效果”或关闭该 Agent 游走时，不进行位置移动。
- 多只桌宠的碰撞规避作为后续增强，不阻塞首版。

### 4.5 鼠标拖动

- 在角色实体区域按下并移动超过点击阈值后进入拖动，透明区域不拦截鼠标。
- 拖动时暂停游走并播放提起/被抓取动作。
- 松开后将角色限制在当前显示器可用区域内，保存该框架的显示器与位置。
- 单击与拖动必须区分；拖动结束不能误触气泡或右键菜单。
- 显示器拔插后，如果原位置不可见，自动迁移到最近可用屏幕。

## 5. 右键菜单草案

遵循 macOS 上下文菜单惯例：只放当前对象相关的高频命令，最多一层子菜单，不可用项按上下文隐藏。

```text
Kimi Code · 执行完毕                 ← 仅用于明确菜单作用对象
打开最新响应并跳转                   ← 仅有最终结果时出现
────────────────────────
切换形象 ▸
  默认 Q 版角色
  其他官方角色…
结果气泡 ✓
游走设置 ▸
  启用游走 ✓
  ─────────
  慢速 / 标准 / 快速
始终置顶 ✓
隐藏并暂停监控
────────────────────────
打开控制面板…
退出 iToppy
```

说明：

- 菜单标题可以根据状态变为“Kimi Code · 运行中”等。
- 结果气泡、游走开关和速度只覆写当前来源实例，不影响同 App 的其他实例。
- “切换形象”和“游走设置”都只有一级子菜单，更多管理进入控制面板。
- 所有右键命令在控制面板或主菜单中也应有入口，不能只存在于右键菜单。
- 首版不在右键菜单塞入路径编辑、适配器诊断等低频设置。

## 6. 官方角色与全身相位图制作框架

### 6.1 最终形态：全身 Sprite Sheet，不是 Live2D 运行时

官方角色最终交付物是**完整人体/角色的透明相位图和 Sprite Sheet**。每一帧都包含完整角色，而不是由产品运行时拼接关节或驱动 Live2D 模型。

- 运行时使用轻量 Sprite Sheet 播放器切帧、镜像、位移和播放动作。
- 首版播放器优先验证 Canvas 2D；只有性能或功能证明有必要时才评估 PixiJS 等渲染框架。
- 不引入 Live2D SDK，不要求用户安装 Live2D，也不把骨架作为运行时依赖。
- 骨架、网格或姿态估计只是制作端可选的辅助工具，不能改变最终交付全身相位图这一目标。

### 6.2 官方制作管线

首版只提供官方角色，由项目成员与制作助手共同生成和修帧，不向用户开放生成入口。

```text
确认角色设定图和标准全身姿态
  → 制作各动作的全身关键姿态
  → 可选使用关节/网格辅助保持动作结构
  → 人工修正脸、服装、四肢和透明边缘
  → 统一画布、脚底锚点和角色比例
  → 导出完整角色透明相位帧
  → 打包 Sprite Sheet 并回读验收
```

不建议把每个动作完全交给模型独立重画。制作时可以借助现有图像生成/编辑工具产出候选关键帧，也可以用骨架/网格辅助形变，但必须通过统一设定图、参考图和人工修帧控制一致性。

制作端暂不锁定第三方动画框架：优先验证“现有图像工具 + 自有离线帧整理工具 + 人工修帧”的小样。只有该路线无法满足质量时，才评估 Spine、Live2D 等制作工具，并且即使使用也只导出全身帧，不引入其运行时。

### 6.3 动作模板

动作至少覆盖：

- idle：呼吸、眨眼和轻微重心变化。
- walk_left / walk_right：可无缝循环的全身行走相位帧。
- running.generic：通用专注工作动作。
- running.thinking：思考动作。
- running.tool_calling：工具调用动作。
- running.searching：搜索动作。
- succeeded / failed：一次性情绪动作加可循环结束姿态。
- succeeded_idle / failed_idle：低强度循环。
- dragging：被鼠标提起时的姿态。

“相位图”指一个动作循环中的完整角色关键姿态帧，例如行走循环的触地、抬腿、经过和换脚阶段。帧数、帧率和画布规格由 P0-5 小样验证后确定。

### 6.4 官方修帧与质量控制

制作流程保留可修正中间结果：

- 角色设定图和标准姿态。
- 可选的遮罩、关节、分层或网格辅助数据。
- 每个动作的全身相位帧预览。
- 脚底锚点、边界框和循环接缝检查。

自动结果不准确时由制作人员修正，不向首版用户暴露关节编辑或遮罩编辑。脸、服装、体型或四肢明显不一致的帧不能进入官方角色包。

### 6.5 角色包草案

```text
character.json       名称、版本、画布、锚点、动作和帧索引
thumbnail            选择列表缩略图
spritesheets/        各动作的全身透明相位图集
source/              可选的官方制作源文件，不随运行时加载
license              来源与授权信息
```

运行时只读取角色元数据和 Sprite Sheet，不加载制作源文件，不持续调用在线生成服务。

### 6.6 可借鉴案例与限制

Meta Animated Drawings 展示了单图分割、姿态估计、绑定、动作重定向和透明动画导出的可行性，可作为制作端辅助流程参考；但仓库已归档，不能直接视为持续维护的生产依赖。

Live2D 的网格与变形器仅为制作思路参考。当前方案不采用 Live2D 作为角色格式或产品运行时。

## 7. 新增前置验证

除原计划外，需要增加或调整：

- **发现扫描**：验证只检查默认/手动路径时的准确率、去重、权限和启动耗时。
- **控制面板联动**：验证隐藏、恢复、手动目录失效、同框架多实例聚合和 per-Agent 设置。
- **running 子动作**：用真实记录验证思考、工具调用、搜索输出不会提前结束任务。
- **气泡与跳转**：验证 50 字截断、中英文/emoji、屏幕边缘、关闭与点击热区。
- **游走与拖动**：验证点击阈值、焦点、跨显示器、边缘转向和动画切换。
- **官方全身相位帧**：以一个 Q 版人形小样验证设定一致性、行走循环、running 子动作、成功/失败动作和播放性能。

官方角色制作与 Kimi Code 监控可以独立开发、独立验收，但共享角色包和动画运行时接口。

## 8. 已确认的设计默认值

1. 首次启动先展示 Agent 选择页，后续沿用用户选择。
2. 手动隐藏实例同时暂停其监控，重新显示时恢复；结果保留期结束后不自动隐藏。
3. 新鲜成功/失败结果暂停游走并按当前实例设置展示气泡；进入 `_idle` 后允许随机游走和长待机动作，桌宠、结果和气泡继续保留，直到用户关闭或新任务到来。
4. 点击气泡跳转，角色身体用于拖动。
5. 游走开关、速度和结果气泡采用“App 默认值 + 实例覆写”，右键菜单只修改当前实例。
6. running 根据明确输出展示思考、工具调用和搜索子动作，最终成功/失败才结束 running。
7. 首版只提供官方角色，由项目成员与制作助手共同生成和修帧，不开放用户生成。
8. 官方角色最终使用全身透明相位图和 Sprite Sheet，不采用 Live2D 运行时。
